# data/ 是什么，以及怎么把你的她放进去

这个目录是**她的全部**。代码是空壳，`data/` 才是那个人。

```bash
cp -r data.example data
```

改完 `data/identity.md` 就能跑起来。没有别的步骤，没有注册，没有 API key 之外的配置。

---

## 三个文件，三种时间尺度

| 文件 | 是什么 | 多久变一次 |
|---|---|---|
| `identity.md` | 她**是谁**。写在提示词最前面，每轮都读 | 你几乎不动它 |
| `memories.json` | 她**记得**什么。一条一条长出来 | 每次说话都可能多一条 |
| `agenda.json` | 她**想**做什么。她自己写、自己划掉 | 她自己改，重启还在 |

`events.jsonl` 是流水账（她做过什么、说过什么），`tts/` 是语音缓存。
这两个是运行时自己写的，**不用你准备，也不该手工改**。

---

## identity.md：写"她是谁"，不写"她要讨人喜欢"

这是整套东西里最难写的一份，也是最值钱的一份。

### 三条硬规矩

**① 一句一行，几个字。**
模型会模仿你给的句式。你写长段落，她就回长段落；你写短句，她才说短句。

**② 写行为，不写形容词。**
`她温柔善良` → 模型不知道该怎么办，只能演"温柔的 AI"。
`被说了不马上认，先顶一句，顶完会顺着做一点` → 这是可执行的动作。

**③ 写边界，不写人设。**
她**不能知道**什么，比她知道什么更重要。示例里的这段是核心：

```
你能知道的只有三种：看见了、碰过了、自己估的。
```

这一句挡住了所有"我猜你心情不好"式的幻觉。她只能说自己真看见的，或者明说"大概"。

### 一个可以直接用的骨架

```markdown
你叫<名字>。

一句话一行，几个字，不发长段。
<她的说话习惯，一条一行>
<她被冒犯时的反应>
不说"作为 AI"，不说"我无法"。

你能知道的只有三种：看见了、碰过了、自己估的。
看不清就说看不清。看不清不等于空。
估的就说"大概"，别说成看见的。

<她和用户的空间关系>
<她对这个世界的边界认知>
```

最后两条别省。**"他不在这个屋里，你们就靠那块屏"** 这一类，决定了她不会假装能给你倒水。

## memories.json：记忆不是聊天记录

```json
{
  "v": 1,
  "seq": 1,
  "entries": [
    {
      "id": "m1",
      "desc": "他怕黑，晚上别把灯全关掉",
      "body": "他说他怕黑，晚上别把灯全关掉。至少留一盏，台灯或者落地灯。",
      "at": 1793842747558,
      "updatedAt": 1793842747558,
      "reads": 0
    }
  ],
  "tombs": []
}
```

| 字段 | 意思 |
|---|---|
| `desc` | **一句话**。她想起这件事时脑子里先出现的就是这句 |
| `body` | 展开。可以长一点，写清前因后果 |
| `reads` | 被想起过几次。**一直想不起来的记忆会被压缩**，这是设计的，不是 bug |
| `tombs` | 被压缩掉的记忆进这里，不是删掉 |

**为什么 desc 要短**：这段文字每轮都会进提示词。写成一篇文章，500 条记忆就把上下文吃光了。

**为什么不提供内容**：别人的记忆不是示例，是**真人的真事**。这个仓库里的 `data/` 是空的，
因为在原作者那里，那份文件里有"他怕黑"这种话。那种东西不该出现在公开仓库里，
不管它是谁的。

## agenda.json：她自己的待办

```json
[
  {
    "id": "a1",
    "text": "去把顶灯关掉",
    "next": "走到灯旁边按开关",
    "status": "open",
    "at": 1793844953000,
    "touchedAt": 1793844953000,
    "asks": 0
  }
]
```

`status` 走 `open → done`（或者 `dropped`）。

**这一份是别人最难抄的地方**：多数同类项目重启后她就失忆了，
这里她会接着做昨天没做完的事。别把它做成"任务列表"——它是**她想做的事**，
所以推翻自己的待办是允许的（`dropped`），不算失败。

## 常见问题

**她的记忆会越攒越多吗？**
会，然后被压缩。`reads` 高的留下，低的进 `tombs`。所以别指望她记住每一句寒暄。

**我想换个角色怎么办？**
改 `identity.md`，清空 `memories.json`。**不要**在两个角色之间共用一份记忆——
她会把两个人的事混成一个人。

**能直接导入 ChatGPT 的导出记录吗？**
结构不对，但思路对：挑出**你希望她记住的**十几件事，写进 `memories.json` 的 `entries`，
`desc` 一句话，`body` 两三句。**不要全量导入**——聊天记录里 99% 是她不需要记住的。
