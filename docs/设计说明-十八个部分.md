## 目的：一句话

**让大模型扮演的这个人，想干什么的时候可以自己动；关掉再开，还是原来那一个。**

**而且没人叫她的时候，她也得过日子。** 这一条是这份文档里所有取舍的来源，
展开在 `宪法-一个活着的人-v1.md`；冲突时以那份为准。

有两件事是**故意不做**的，因为它们和上面那句话冲突：

1. **不定时叫醒她。** 定时器（每 60 秒说句话、整点想起一件事）锁死的是"什么时候动"——
   那是钟在替她决定。她只在"注意到一件事"或"自己记下一件事"的时候醒。
   代价是她不会无缘无故开口。这是要付的代价，不是缺陷。
2. **不训练。** 人格靠人设 + 记忆 + 少量示例，零门槛，缺点在 `定位-能力边界与分工` 里写清了。

## 一条主干

```
他说一句话 / 屋子里有件事变了 / 她自己记的事到点了
   ↓ ① memory.record()          先落盘：模型挂了，这件事也已经发生了
   ↓ ② memory.boot()            身份 → 现在（几点 + 距上次多久）→ 议程 → 记忆索引 → 最近三件 → 关系
   ↓ ③ prompt.buildSystem()     加上「记忆怎么用」「手上的事」「这屋里有什么」「这次能做什么」「你这具身体」
   ↓ ④ /api/chat                拿到 {"say","read","remember","forget","plan","done","do"}
   ↓ ④.5 memory.readMem()       她要正文才给正文，再把正文附上一次重问（只一轮）
   ↓ ⑤ executor.run(do)         **只有这一处碰世界**：屋子 / 游戏 / 身体三个端口，最多两步
   ↓ ⑤.5 registry.call()        屋子算出坐标、走过去、坐下；大脑只递 id
   ↓ ⑤.6 avatar.say/emotion     说话、表情走身体端口；这具身体不会就降级，降级要说出来
   ↓ ⑥ memory.record()          她说的、做成的、没做成的、记住的、记下的，都写回去
```

**⑤ 和 ⑤.5 之间那道线是硬的**：`loop.mjs` 只产出意向，不许自己调 registry、不许碰 avatar。
写了就过不了 `executor-test` 的源码断言（E6/E7/E8）。

## 十八个部分：各自的目的、设计、用处

### 1. `js/brain/memory.mjs` —— 重启之后还是她

**目的**：模型没有内隐记忆，重启后什么都不剩。所以"回忆起之前的事"在技术上不是"想起来"，
是**启动时按固定顺序重建一遍**。这个文件就是那套重建。

**怎么设计的**
- **五份文件分开存**，因为它们的更新频率差三个数量级：身份（几乎不变）/ 世界快照（每帧）/ 议程（一天几条）/
  事件流（只增）/ 关系（每天一句）。混在一个文件里，任何一次写都会把别的覆盖掉。
- **开机六块，顺序是硬的**：身份（逐字，不许压缩）→ 现在（绝对时间 + 距上次多久）→ 议程 → 记忆索引 →
  最近三件（只装事实，不装她自己的话）→ 关系一句。预算 1400 字，超了**整块丢**，不截断。
- **记忆是两层**：索引（每条一行，全给，不筛）+ 正文（她自己 `read` 才给）。
  以前是开机时用关键词打分替她挑三条塞进去——那不叫"她想起了"，是外置算法替她决定想起什么，
  挑错了她看不见。现在判断权在她。
- **删是墓碑**：`forget` 不真删，记一个 `tombs`，同 id 再写回会被拒。记忆一旦能凭空消失，
  "她记得"这件事就没法验证了。

**有什么用**：她今天说的话，明天开机还认；她做过的事，重启后翻得到；换台机器，把 `data/` 拷过去还是她。

**不做什么**：不调模型、不碰 DOM、不依赖 fs（存储接口注入，浏览器换 localStorage 一行不用改）。

### 2. `agenda`（在 memory 里）+ `js/brain/initiative.mjs` —— 自主的两个来源

**目的**：让"想干什么"真的来自她，不是来自我们写的一串 if。

**怎么设计的**
- 自主只有**两个来源**，缺一不可：
  - **外界有事**（`initiative`）：灯灭了、他走了、她说的话没人接。五个封闭原因码
    `repeat | unseen | no_response | unfinished | signal`，屋子只能往里放这五种之一。
  - **她自己的议程**（`agenda.json`）：没人吩咐时她自己记下的"我想做这个"。
- 议程是**她的输出字段**，不是系统的定时任务：`plan` 写、`done` 划。
  写完落盘，重启还在；开机时带 id 和"这是多久以前写的"。
- **同一条议程最多自动问三次**（`asks`）。她可以不做，但不能一直挂着假装要做——
  否则每次没人说话都把它捞出来问一遍，那不是自主，是被追债。问满三次就不再主动提。
- 派发顺序：**外界的事优先，然后才是议程**。外界的事是"现在"，议程是"我想"。

**有什么用**：进屋十分钟没人说话，她做了 1 件自己写的事；重启后那件事还在队列里。
这是"自主"唯一能被验证的形态——不是她说"我很自主"，是日志里有一条她自己写、自己做的记录。

**不做什么**：不按时间派发（没有"每 N 秒"），不替她生成议程（`plan` 只能她自己说）。

### 3. `js/brain/perception.mjs` + `world.mjs` —— 她怎么"注意到"

**目的**：把"屋子里发生了什么"变成"值得看一眼"，但**只报告，不反应**。

**怎么设计的**
- 世界是一张**固定形状的快照**：姿态 / 身边最近的东西 / 各处开关 / 他在不在。**不许有坐标**——
  坐标一进来，模型就会开始算距离，而"怎么走过去"是屋子的事。
- **前后两张快照做差**，只报变了什么。没变就一个字节都不产生，不调模型。
- 规则表（`rules/room.json`）只负责"这件事值得一顾"，**不挑动作**。
  上一版让规则直接选动作，等于外面替她决定，被否掉了。
- 三条护栏，都是真跑踩出来的：**空快照不算"所有灯都灭了"**；**不知道他在不在（null）不算"他走了"**；
  **开机第一次只立基线**，不然"灯本来是亮的"会被当成"灯刚被打开"。

**有什么用**：他关灯、拉窗帘、走开、回来，她都能注意到，而且只注意到一次。

### 4. `js/brain/prompt.mjs` —— 把上面这些说成人话，再把人话解析回来

**目的**：模型只认文本。这个文件负责"说什么"和"听懂什么"。

**怎么设计的**
- 系统消息由几块拼成：启动块 + **记忆怎么用**（纪律）+ **手上的事**（议程纪律）+ 这屋里有什么（点名 id）
  + 这次能做什么（窗口）+ 输出契约 + 末尾核对姿势。
- 输出是一个 JSON，但**不要求整段只有 JSON**：先剥代码围栏、再取最外层花括号，解析失败就把原文当话说。
  宁可少动一下，不可因为格式崩掉。
- 格式不对**重发一次**（把那句当 assistant 消息塞回去，加一句"只发 JSON"）。只重发一次。
- 几条纪律不是拍脑袋：`remember` 要带 id 改、大多数轮次不用记、`plan` 不是待办清单、
  "只做一步就只说这一步"——每一条都对应一种真跑见过的坏法，注释里写了是哪一次。

**有什么用**：她说话像人、动作有目标、不乱记、不把没做成的说成做成了。

### 5. `js/brain/actions.mjs` + `room-bridge.mjs` —— 说"做什么"，不说"怎么动"

**目的**：把大模型的动作空间**关死成枚举**，让它只能表达意图，不能表达几何。

**怎么设计的**
- 注册表只管六件事：名字、描述（描述就是提示词）、参数 schema、校验、超时（20 秒）、失败分类。
- **拒收几何量**：`x/y/z/pos/distance/speed/duration/path/bone` 出现在参数里直接回 `geometry_not_allowed`，
  并告诉她"只说做什么，怎么走过去由屋子算"。
- **动作窗口**（照 Neuro）：一轮只放开该放的几个。窗口外回 `not_in_window`，并告知这次能做什么——
  不是静默消失。
- **注销留 10 秒**：刚被收走的动作回"刚被收走"，不是"没有这个动作"。
- **失败带责任归属** `by: 'her' | 'room'`，message 说人话。这是它能被修的唯一线索。
- 回执写成**她能读的事实**："你坐下了" / "你想坐下，但没成：这件东西坐不上去"。
  不是 `use_furniture：sit`，更不是 `no_such_thing`。

**有什么用**：她说"去椅子上坐会儿"，屋子自己算路、自己走过去、自己坐下；她说错了，回执告诉她错在哪。

### 6. `js/brain/loop.mjs` —— 把上面五件串成一轮

**目的**：一轮对话 / 一次自主行动，只有一份实现。

**怎么设计的**
- `turn()` 五步：先落盘 → 装上下文 → 问模型 → 执行 → 回写。
- `wake()` 只有**有事**才调模型：没有外界的事、也没有议程，就直接返回，不花钱。
  可测指标是 `stats.wakes : stats.wakesWithModel`，接近 1 就说明它退化成了定时器。
- 忙时**排队不丢**：他连着说两句，第二句进队列，这一轮完了接着跑（上限 3 句）。
- 异常也关窗：窗口留着会让下一次对话被上一次的限制卡住。

### 7. 屋子（两个页面）—— 唯一两家都没有的东西

**目的**：她得**在一个地方**，而不是在一张聊天框里。别人能看见她在哪、在做什么。

**怎么设计的**：66 是 three + VRM 的 3D 房间（可走、可坐、灯和窗帘能开关），67 是 Live2D 封面。
两个页面共用同一份记忆和同一个大脑，只是显示端不同。

**它的两条验收**（2026-11-05 定）：
1. **好看是第一要求。** 横屏机位已经调过；竖屏和手机上还不行。
2. **出错不吓到人。** 不崩、不突然黑屏、不静音卡死；报错留得下、查得到、用户自己能修。
   **不追"出错也好看"**——我们没有导播，也不需要有。

**屋子为什么必须存在**（`宪法` 条款 4）：聊天框里没有"刚才"——每一轮都是全新的。
有了屋子才有"我刚才在窗边站着"，而这句话正是"她一个人也活"的燃料。
所以屋子不是布景：**她留下痕迹，回来还在**。（灯/窗帘重启恢复还没做，见"已知的洞"第 2 条。）

### 8. `js/brain/avatar.mjs` —— 换身体不改大脑

**目的**：她这具身体是可换的。换模型、换格式（VRM / Live2D / MMD / Spine / 立绘），
大脑那一侧一行都不用改。

**怎么设计的**
- 七种能力：`say / lipsync / emotion / motion / lookAt / blink / outfit`。
  其中 `lipsync` 和 `blink` 是后端自己在做的（跟音频动嘴、按节奏眨眼），大脑不指挥——
  指挥了反而跟渲染循环抢。
- **后端自己声明能力**。声明了却没实现的，注册时直接拦；没声明的一律够不着，
  不靠"调一下看它崩不崩"来发现。
- **缺能力就降级，而且降级不静默**：立绘不会动，`play('sit')` 退成一次表情变化，
  返回 `{degraded: true, via: 'emotion', message: '这个身体不会做动作，只换了个表情'}`。
  静默降级的后果已经踩过一次——她以为坐下了，人还站着。
- **能力边界和 bug 分开记**：`unsupported`（这个身体本来就不会挥手）vs `threw`（骨骼名找不到）。
  混成一个，排错时永远分不清是改配置还是改代码。
- `describe()` 进提示词。她得知道自己这具身体能做什么，否则会答"我给你跳个舞"，
  而这个模型连手臂都没有——那不是她撒谎，是我们没告诉她。

**五扇门**（`BACKEND_TABLE`）：vrm / live2d / mmd / spine / tachie。
现在只开了 vrm，能力是 `say / emotion / motion / blink`——**没有 lookAt 和 outfit，因为确实做不到**，
所以 `describe()` 会照实说"不能换衣服、不能转头"。另外四门只定了能力表，谁接谁注册。
**不能因为还没内容就不做门**，但也不能开了门假装里面有东西。

**有什么用**：别人拿自己的模型来，注册一个后端就能进这间屋子；换模型不动大脑。

### 9. `js/brain/executor.mjs` —— 思想与行为的分界线

**目的**：让"她决定做什么"和"世界到底有没有做成"是两件事。
写在一处的话，执行失败会**改写决定**——她说过"我坐下了"，其实走位失败了，
下一轮她就接着编"我坐得有点累"。**从此她和现实脱开，而且没人能发现。**

**怎么设计的**
- `loop.mjs` 只产出意向（`do: [{name, args}]`），**不碰世界**；`executor` 是唯一碰世界的地方，**不改意向**。
- 只认三个端口：`room / game / body`。不知道 three、不知道 vrm、不知道 DOM。
- **失败不冒泡**，一律翻译成她能读的一句人话 + 一个原因码
  （`unsupported / no_backend / threw / no_action / bad_arg`）。
- **责任归属** `by: 'her' | 'room' | 'game' | 'body'`——这是唯一的可修线索：
  是她说错了、屋子没这件东西、游戏没接上、还是身体不会做。
- **最多两步**（`MAX_STEPS = 2`），第三步不做并说明为什么停。
- **只有一个出口**：`speak()` / `express()` 也收在这里，否则"说了没做""做了没说"会变成两套账。

**怎么验**：`executor-test.mjs` 54 条，其中 E6/E7/E8 是**读源码**验的——
`loop.mjs` 里出现 `registry.call` 或 `avatar.` 就红。行为断言只能证明这一次没越界，源码断言才能证明结构没坏。

### 10. `js/brain/wardrobe.mjs` —— 骨架是骨架，身体是身体，穿戴是穿戴

**目的**：换衣服不该动模型、不该动大脑。一个人长什么样（骨架 + 身体）和今天穿什么（穿戴）是三件事。

**怎么设计的**
- 六个槽：`body / hair / top / bottom / shoes / accessory`（饰品最多 4 件）。
  **日常只有后五个会被换**，`body` 是换人（换模型）时才动的。
- 三种穿法：`overlay`（一张图贴在骨头上）/ `mesh`（真模型）/ `texture`（改贴图）。
  现在 66 只实现了 `overlay`，另外两种会**如实说"这具身体还不会穿这种"**，不假装穿上。
- **overlay 用 `THREE.Sprite` 而不是 Mesh 平面**：Mesh 平面一转身就变成一条线（真踩过）。
  Sprite 永远面向镜头，配 `depthTest:false` 永远在前面。
- **有图就能生成**：`fromImage({id, slot, image, bone, offset, scale})` 一行出一件。
  不想写代码的走 `衣柜-导入.html`：拖图 → 自动去背 → 滑块调位置 → 写进 `assets/wardrobe/items/`。
- **坏一件不拖垮全部**：`loadWardrobe` 读目录，读不进来的那件记进 `problems`，其余照穿。
- **换骨架自动脱**：`requires.skeleton` 不匹配的件在换骨架时被脱掉，并留 `unequip` 痕。
  不然换个人，围巾还挂在空气里。

**要什么、怎么导入**：`assets/wardrobe/_模板/` 里有 `manifest.json`（带 `_说明` 字段的模板）、
`manifest-3D.json`、`说明.md`、`生成提示词.txt`、`画布-1024x1536.svg`（画的时候按这个尺寸和站位）。
命令行导入：`node tools/wardrobe/make.mjs --image 图.png --slot top --name 我的衣服`。

**不做什么**：不做"照片自动变成衣服"（没有这个能力，硬做出来是一张贴纸）；
不自动选搭配（穿什么由她说，`change_clothes(item: outfit)` 只递 id）。

### 11. `js/brain/game-bridge.mjs` + `games/guess.mjs` —— 让她去玩游戏

**目的**：让她的世界不止这间屋子。游戏对她是**一个可以进去待一会儿的地方**，不是我们要控制的东西。

**怎么设计的**
- 游戏动作注册进**同一张 registry**，schema、动作窗口、20 秒超时、几何量校验**全部复用**，没有第二套。
- **局面只给"人话"**：`state()` / `brief()` 进提示词。坐标、像素、点击位置一律被 `sanitizeState` 拦掉
  （深度 3 层、24 键封顶），**大脑永远不知道屏幕坐标**。
- 撞名报错并回滚（`registry.unregister`），不静默覆盖。
- `stop_game` 是内置动作，**不走 10 秒注销宽限**——她一说停就该停。
- 游戏里发生的事走 `perception.signal()` 投递（事件不是状态，没有"恢复"，所以不做差）。
- `guess.mjs` 是一个真能玩的适配器（猜数字）：重复猜同一个数不算次数，`state()` 回 `{status,tries,lo,hi,last}`。

**真跑过一次**（不是断言）：她拿到局面后自己想到猜 50，回执"你猜 50，大了；范围缩到 1~49"，
下一轮自己说"1 到 49，我接着猜 25"。**这个策略没人教她。**

**不做什么**：不做游戏外挂式的"帮她打"；不做 screen 模式的通用适配器（`assets/games/index.json`
里 `sts` / `opus` 两条 `enabled:false`，列了 `needs`，等真做）。

### 12. `js/brain/world-content.mjs` —— 别人往这个世界里加东西

**目的**：屋子是我们建的，日子不该只有我们能往里添。别人加一道菜、加一个"看窗外"，不改代码。

**怎么设计的**：一个活动一份 JSON（格式和三条禁区见 `宪法` 条款 3）。
只能组合**已有的**动作：走到某件家具、坐下、换个表情。不许写坐标、不许替她说话、不许排时间。
`validateActivity` 对这三样是**硬拦**（当场报错），不是警告。

**加东西的人需要什么**：一个文本编辑器，和"这屋子里有什么"这张表（`__BRAIN.entities()` 会列）。
`assets/world/activities/index.json` 加一行 `file` 就多一件。

**为什么不做成插件代码**：代码插件能做的事太多、门槛也高——会写 JS 的人不需要我们，
会写内容的人被挡在外面。先给"能加一道菜"的格式，真有复杂玩法再开 adapter，那是第二步。

### 13. `js/brain/senses.mjs` —— 她注意到他在动

**目的**：屋子里只有三样东西会变（灯、窗帘、姿态），太少了。他在打字、光标挪到屏幕角上，
这两件事是"陪伴感"的全部来源。

**怎么设计的**
- 光标只报**换区域**（九宫格 `左上/上/右上/…`），同一区域不动不报，节流 800ms。
- 敲键盘**一串报一次**（5000ms），**不记按键值**——"他敲了一下"是事实，"他敲了 a"是内容（可能是密码）。
- 屏幕内容默认**关**，要 `consent(true)`（她得知道自己在看别人的屏幕），开销大、隐私敏感。
- 全部走 `perception.signal()` 事件通道，**不进快照**：这三样都没有"恢复"这回事。
- `consent(false)` 只收回许可，**不关通道**——许可和通道是两件事。

### 14. `js/brain/voice.mjs` + `tools/tts.mjs` —— 让她被听见

**目的**：直播那六条标准里的第一条。没有声音，前面十六条都只是"一个人在打字跟一个模型聊天"。

**怎么设计的**
- **合成是一个端口**：`POST /api/tts` 一句话进、一段 wav 出；引擎是一张表
  （`sapi` 本机离线 / `edge` 在线 / `stub` 只给测试）。换音色换引擎只动那张表。
- **说 = 字幕 + 声音**，落在 `avatar.say` 一处（`executor.speak()` 是唯一出口，身体负责让她被看见**和**被听见）。
- **口型看波形，不看文本**：`AnalyserNode` 算 RMS → `avatar.lipsync(v)` → 3D 那边的 `mouthWant`。
  不建音素词典，换语言、换句子都不用改。
- **没声音不许装死**：返回 `{ok:false, reason, message}`，字幕照常、嘴保持闭合（不演"在说话"）。
  只有第一次会去问服务端，之后不再重复问。
- **一个人不能同时说两句**：新的一句直接把旧的停掉（`voice.stop()`），不叠音。
- **自动播放限制**：用户第一次点/敲页面时解锁 `AudioContext`。不解锁的话声音"在走"但一个采样都不出——
  真跑抓到过，表现和"口型坏了"一模一样。

### 15. `loop.hear` / `loop.interrupt` —— 她真的在听（2026-11-05）

**目的**：他说话的时候她正在想/正在做，那句不能被吞掉；而"听见"和"打断"是两件事。

**怎么设计的**
- **话先落盘**：`hear()` 不管她在不在忙，先 `memory.record`。忙的时候置一个 `owed`，这一轮完了接一句。
- **只掐"正在想"**：一次 HTTP 请求掐掉不损失什么；已经在走路的腿掐不掉，硬掐会把她卡在半路。
  **要不要放下手上的事，是她下一轮读到之后自己的判断**（这一条不能省）。
- **打断不是故障**：不记 error、不弹红字，只留一条事实"话说到一半被打断了"。
- **迟到的结果不许落地**：`epoch` + `AbortController` 双保险——底层不听 signal 时，代数那一层也会作废。
- **别人的话带名字**：`[小明] 你好`。原来非她的话一律当 assistant，第三个人一进来就会变成"她自己说的"。

### 16. `js/brain/chat-in.mjs` —— 外面的话怎么进来（2026-11-05）

**目的**：弹幕/群聊/语音转写/别的程序，都从一个口进来。**收下 ≠ 要回。**

**怎么设计的**
- 落盘只走 `loop.hear()`；合并同一人同一句（4 秒内）；待看超 20 条挤掉最旧的，**计数 + 留痕**。
- **时机策略只管流量**：`every`（一个人聊）/ `window`（默认，攒 1.2 秒）/ `never`（只收，等她自己醒）。
- **不许在收的时候替她挑"这条值得回"**：那是外部算法替她想。要过滤在入口外面过滤，或让她自己在提示词里挑。
- 来源是适配器：`{id, start(emit), stop}`，一个起不来不拖垮其余。
- 外部投递：`POST /api/in` → 服务端广播 → 页面 `GET /api/in/stream`（SSE，没人听时排队 50 条）。

### 17. 看门狗 —— 跑一晚上不能停在"她在想…"（2026-11-05）

**目的**：页面卡死时它救不了自己，只有外面能拉它。

**怎么设计的**
- 页面每 30 秒 `POST /api/alive`（`js/brain/heartbeat.mjs`，**页面里唯一的定时器，且只做这一件事**）。
- 服务端只记"我多久没听见了"（90 秒 = 3 倍间隔），`/api/health` 里报 `alive.stalled`。
- **决定重载的是桌面壳**（它手里才有窗口）：一分钟内最多一次；服务连不上不重载。
- 另一道兜底在锁上：`loop` 里超过 90 秒没回来的那一轮自动放开，晚回来的结果按代数作废。

### 18. 流式 —— 她开口不用等整段写完（2026-11-05）

**目的**：整段等 2–8 秒才听到第一句，人不是这么说话的。

**怎么设计的**
- **流只改运输**：`/api/chat` 加 `stream:true` 走 SSE；`js/brain/sse.mjs` 分帧；`js/brain/say-stream.mjs` 从还没写完的 JSON 里抠 `say`。
- **只说整句**：句末标点到了才放出去（半句收不回）；不是 JSON 就一个字都不提前说（散文多半会被重发换掉）。
- **同一轮里说过话，后面就不再接流**：格式重发、取正文再来一次都算——两段会拼成一句她没说过的话。
- **定稿只补没说过的**：按字对齐（模型爱用 `"  \n"` 断句，按长度切会切在字中间）。
- **打断是真的**：`AbortController` → 服务端 `destroy` 上游请求。实测 900ms 时插话，上游在 923ms 被切断。
- **逐句出声要排队**：`voice.speak` 一进去就会掐掉上一句，所以流式逐句必须走 `speakQueued`
  （等 `onended` 再念下一句，带超时兜底）；被打断时整队作废，不许把排着的那几句念完。
- **三档可退**：`?stream=off`（老整段）/ `?stream=quiet`（只流不说）/ `?stream=speak`（默认）。
- 内容和判断一个字都没动：先说出去的永远是模型已经写下的原文。
