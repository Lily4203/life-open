# adapters/ —— 外线插槽

**往这个目录里放一个 `.mjs`，重启服务，就接上一条线。** 不用改服务端代码，不用改页面。

线是什么：QQ 群、B 站弹幕、小黑盒、别的游戏、你写的一个只会在整点时说话的脚本。
它们全都只做一件事——**往屋子里送一句话**。剩下的事（收下、落盘、攒批、她回不回）在 `js/brain/chat-in.mjs` 那层，已经写好了。

---

## 一、一个适配器长什么样

```js
// adapters/clock.mjs
export default {
  id: 'clock',                 // 必填。小写蛇形，唯一，重名当场报错
  label: '整点报时',            // 人看的名字
  where: '墙上',                // 这些话在她世界里从哪来（可选，见下）

  start(send) {                // 必填
    this.t = setInterval(() => {
      send({ text: `${new Date().getHours()} 点了。`, from: 'clock', name: '钟' });
    }, 3600e3);
  },

  stop() { clearInterval(this.t); },        // 可选
  state() { return { on: !!this.t }; },     // 可选，进 /api/health
};
```

改完重启 `node tools/serve.mjs`，启动日志里会多一行：

```
[serve] 外线：clock（整点报时 · 墙上）
```

她那边看到的是记忆里多出一条 `guest:clock` 说的话，标签写作 `[钟·墙上]`。

## 二、`send()` 的参数

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 一句话。空白会被丢掉（`{ok:false, reason:'empty'}`），超 500 字截断 |
| `from` | 否 | 谁说的。默认就是你的 `id` → 她看到 `guest:clock`。他本人是 `'him'` |
| `name` | 否 | 显示名。没有就用 `from` 去掉前缀，**不编一个"网友123"** |
| `source` | 否 | 只能是 `local` / `danmaku` / `group` / `voice` / `script` / `game`，别的会被退回 `script` |
| `where` | 否 | 覆盖适配器级的 `where`。比如同一条线里区分"手机"和"平板" |

`where` 是最容易被忽略、又最影响她说话的一个：写了，她就知道"这话是从我手机上来的"；
不写，她只看见一个人说了句话，不知道从哪来——**她不会猜，我们也别替她编**。

## 三、三条硬规矩

1. **一条线起不来，不许把别的拖下水。** 你的 `import` 失败、`start` 抛错，只会让你这条线在 health 里标红，别的照跑。
2. **失败必须留痕。** 别把异常吞掉——`state()` 里返回 `{ connected: false, why: '…' }`，人一眼能看见。静默的插件比没有插件更难查。
3. **不要在这里判断"她要不要回"。** 按关键词、按 @、按"这条有没有意思"过滤，都是外部算法替她想。想少收，就在 `send` 之前不调；**收了却不说，和丢了没区别。**

## 四、怎么验（不用等真有人发消息）

```bash
curl -s http://127.0.0.1:8765/api/health | python -m json.tool | sed -n '/adapters/,/]/p'
```

应该看到：

```json
"adapters": [
  { "id": "clock", "label": "整点报时", "where": "墙上",
    "started": true, "sent": 1, "errors": 0, "idleMs": 120000,
    "state": { "on": true } }
]
```

`started:false` 或 `error` 非空 = 你这条线没起来，重启日志里会写原因。
`sent` 一直是 0 = 起来了但从没发过东西（可能是协议端没连上，去 `state()` 里看）。

## 六、已经知道的三条边界

- **页面没开的时候，消息最多排 50 条**，再多就丢（`/api/health` 里的 `inbox.dropped`）。这是"她不在场"，不是 bug。
- **她回不回，不归这里管。** 有人说话 → 她可以选择不接（见契约 2.26）。你的线只管把话送到。
- **群聊要自己控节奏。** 实测过：3 句隔 2.6 秒，她会 3 次都接。真进群之前，这条线里得有个"说完之后的冷却"——但那是**时间**上的冷却，不许按内容挑。
