# 角色注册表 · `characters.json`

> 版本：schema 2 · 2026-11-05
> 这份文件的形状，决定"换人"能不能只改数据、不改代码。

---

## 一、为什么不是一个角色一个模型

最早的写法是 `{ id, name, file }`：一个角色对应一个模型文件。这个写法在遇到下面这件事时立刻崩了：

**一个角色可以同时有 Live2D 和 VRM 两套。**

- Live2D：画好的平面图，509 个参数、23 个表情。干净、好看，**但不能坐、不能躺、手碰不到桌子**。
- VRM：3D 骨骼，能走能坐能躺。但 AI 生成的贴图自带烘死的光影，**在实时渲染里会显脏**。

它们不是"新旧两版"，是**同一个人的两套皮**，各有各的用处。所以数据模型必须允许一个角色挂多具身体：

```
角色（人设 / 声音 / 记忆 / 聊天历史）
  └── 身体 ×N（VRM / Live2D / 以后 MMD、Spine、立绘）
```

这个结构是照 AIRI 的 `CHARACTER }o--o{ DISPLAY_MODEL` 学的。它们的 ADR 里有一句话很关键：

> A character holds `avatarModels` and `defaultAvatarModelId`.
> Many characters can refer to one display model.

**多具身体可以共用同一个模型文件**（比如两个角色都用同一个底模），所以"身体"是引用，不是拷贝。

## 二、字段

### 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `schemaVersion` | ✓ | 现在是 `2`。读到 1 或没有，会按旧格式兼容（一个角色一个 `file`） |
| `canonHeight` | ✓ | 世界尺度基准，`1.357`。房间、家具、坐姿全按它做 |
| `characters[]` | ✓ | 角色数组 |

### 角色

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | **稳定标识**。聊天记录、记忆以后都挂在这个 id 上，**改了会丢历史** |
| `name` | ✓ | 显示名 |
| `avatarModels[]` | ✓ | 身体数组，至少一条 |
| `defaultAvatarModelId` | | 打开时优先用哪具。找不到就按场景挑 |
| `aka` / `note` | | 别名 / 备注，不参与逻辑 |

### 身体

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 身体标识，同一个角色内唯一 |
| `kind` | ✓ | `vrm` ｜ `live2d`（以后可扩 `mmd` / `spine` / `tachie`） |
| `src` | ✓ | 相对路径 |
| `use` | ✓ | **这具身体能进哪些场景**：`cover` 封面 / `chat` 对话 / `room` 房间 |
| `label` | | 面板上显示的名字，如 `3D`、`Live2D` |
| `credit` | ✓ | **授权信息跟着身体走**，不跟着角色走 |
| `hide` | | 仅 VRM：进场要隐藏的网格名 |
| `tail` | | 仅 VRM：尾巴骨骼名 |

**`credit` 为什么挂在身体上：** 同一个角色的两套皮，作者常常不是一个人（同一个角色的两套皮，画师和建模师常常不是一个人）。授权条件也不同。混成一个字段就会写错署名——而署名写错是侵权，不是笔误。

```jsonc
"credit": {
  "author": "作者名",              // 或 "art" / "rig" 分开写
  "license": "CC BY-NC-SA 4.0 · 禁二次分发/商用",
  "commercial": false              // 拿去做商业演示前必须为 true，否则要谈授权
}
```

## 三、场景怎么挑身体

代码里只有一个函数，规则写死：

```
room  →  kind === 'vrm'                    没有就提示"换个角色或导入 .vrm"
cover →  kind === 'live2d' 且 use 含 cover
         → 否则第一个 live2d
         → 否则第一具身体（并 warn）
```

`defaultAvatarModelId` 优先级最高，但**必须满足场景要求**才算数——否则"默认是 Live2D"会让房间打不开。

用 `?avatar=` 可以强制指定（`?avatar=vrm` / `?avatar=fish-l2d`），调试用。

## 四、加东西的四种操作

### 给现有角色加一具新身体

在 `avatarModels` 里加一条。**不改代码、不改房间、不改互动。**

```jsonc
{
  "id": "fish-vrm2", "kind": "vrm", "label": "3D 新版",
  "src": "assets/vrm/fish-v2.vrm",
  "use": ["room"],
  "credit": { "author": "某人", "license": "自建", "commercial": true }
}
```

### 加一个新角色

复制整个角色对象，换 `id`（**不能重复**）和身体。人设、记忆是另一套系统的事，这里只管"能不能显示"。

### 换封面用的模型

改 `cover` 场景那具身体的 `src`。封面页只认 `kind: live2d`。

### 让一个角色只当立绘（不进房间）

只给 `use: ["cover", "chat"]` 的身体。房间面板会把它标成"没有 3D 身体，进不了房间"，点它会有明确提示，不会崩。

## 五、契约（房间对她的要求）

不管哪具身体进来，只要 `kind: vrm`，就必须满足：

1. **身高归一到 `canonHeight`**：代码会按包围盒自动缩放，但要求模型是"站直、脚在原点"
2. **脚在 y=0**：房间的地板是 y=0
3. **面朝 +z**：VRM 0.x 会自动绕 Y 转 180°（`metaVersion === '0'`）
4. **人形骨齐全**：至少 hips / upperLeg / lowerLeg / foot / shoulder / upperArm / lowerArm / hand
   缺骨不算失败——`measure()` 会逐项回退到基准 `B`，功能降级但不崩

这四条不满足也不会崩，但家具会对不上（坐不进椅子、躺不下床）。

## 六、已知问题

| 问题 | 状态 | 说明 |
|---|---|---|
| 封面模型鼻梁处有黑色残留 | **已解决（2026-11-05）** | 根因是贴图里的一块孤立残留，已在 `tools/l2d_shrink.py` 里抹掉，见下 |
| Live2D 进不了房间 | 设计如此 | 无骨骼，无法坐躺。已做明确提示，不静默失败 |
| `canonHeight` 改了就全套崩 | 已知 | 家具尺寸是按 1.357 反推的，改它要重算全部家具 |

### 黑色残留：最终结论与修复

现象：鼻梁位置一个约 14×18 屏幕像素的黑色圆角方块。随模型缩放，位置固定在脸上。

已经排除的：

| 假设 | 怎么排除的 | 结果 |
|---|---|---|
| 我压缩纹理搞坏了 | 用原版 `body/your-avatar/model.model3.json` 渲染（`?l2d=` 生效，纹理尺寸 4096×8192 已核对） | 一样有 → 排除 |
| 某个 Part 的透明度 | 147 个 part 的 opacity 全是 1.0 | 无法用 part 控制 |
| `眼镜`/`黑矿眼镜`/`加载`/`按键` 部件 | 逐个 kill Part77/73/74/26/19/64 | 都不消失 |
| `key11 黑框眼镜` 等按键参数 | 读值全是 0（本该关着） | 不是它的开关 |
| `Param140 加载` | 值为 0 | 排除 |
| 是 DOM 覆盖层 | 遍历所有元素（含 `pointer-events:none`），按相对坐标命中 | 只有 canvas 与全屏光效层 |
| 是 drawable | **全关 715 个 drawable**（opacities=0 + dynamicFlags\|4）| 角色几乎消失（暗像素数万→875），**黑块仍是 196** |
| pixi 舞台上的其他对象 | `app.stage.children` 只有一个 model，无 mask、无 filters | 排除 |
| **是贴图** | **逐张纹理置为纯白**：只有 tex0 置白时黑块消失 | **命中 texture_00.png** |

**根因**：`texture_00.png` 的 (873..899, 577..682)（1024×2048 坐标）有一根孤立的黑色模糊竖条，
四周 alpha 全 0、没有任何其他 drawable 采样它。它是原模型里的一块残留件。

**修复**：`tools/l2d_shrink.py` 里的 `ERASE` 列表，按归一化坐标抹掉 alpha（羽化 4px，不动 RGB 避免色边）。
重新生成后验证：黑块区暗像素 180 → 0，脸部干净。

**没有走"重导出"这条路的原因**：moc3 是编译后的二进制，**没有 `.cmo3` 工程文件**，
Cubism Editor 打不开，所以"打开模型删部件再导出"在只有运行时资源的条件下不成立。
贴图级修补是唯一可行的做法，而且可复现（脚本化、随尺寸缩放）。

辅助脚本 `tools/find_black_drawable.py` 留着：它对"在 drawable 层"的瑕疵有效，
本例正是反例（第一次跑就报告"全关都没变化"）。将来换模型再遇到，正确顺序是：

1. `m.visible=false` → 黑块还在吗？（不在就说明确实在模型里）
2. 逐张纹理置白 → 定位到哪张图集
3. 读该位置 drawable 的 `vertexUvs` → uv → 图集像素坐标（注意 `uv.v` 要翻转：`y=(1-v)*H`）
4. 在 `l2d_shrink.py` 的 `ERASE` 里加一条，重新生成

## 七、和 AIRI 的差别

| | AIRI | 我们 |
|---|---|---|
| 关系 | `CHARACTER }o--o{ DISPLAY_MODEL` | 同（照抄） |
| 存储 | Pinia store + DuckDB | 一个 JSON 文件 |
| 身体的场景声明 | 无（所有后端都能上舞台） | **`use` 字段**：Live2D 进不了房间，必须显式声明 |
| 授权 | 没在数据模型里 | **`credit` 挂在身体上**，因为同一角色两套皮常不同作者 |

第三行是我们多出来的一条：AIRI 的舞台"什么后端都能上"，我们的房间不行——**房间对骨骼有硬要求**。这个差异必须写进数据里，否则 UI 会让用户选一个必然失败的东西。
