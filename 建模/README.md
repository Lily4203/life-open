# 建模：开源版为什么是毛坯房，怎么把自己的身体装进来

开源版**不带任何模型**。不是忘了打包，是三条都绕不过去：

1. **授权**。第三方 VRM 的条款通常写死"禁止二次分发"。放进公开仓库，
   违约的是"分发者"——也就是你。
2. **体积**。一个 VRM 几十 MB，二进制一旦进了 git 历史就永远删不掉，
   以后每个 clone 的人都要为它付一次流量。
3. **这是"她的内容"，不是"框架"**。框架的价值随用户数涨，内容的价值随时间涨。
   我们做的是前者，后者该由每个人自己填。

所以这里只给**接口**和**说明书**。房间能跑，但里面没有人；家具是纯色方块。
放一个模型进去，它才成为"一个住处"。

---

## 一、身体接口在哪

| 位置 | 管什么 |
|---|---|
| `assets/characters.json` | 角色注册表：一个角色 = 一份人设 + 多套身体 |
| `assets/vrm/` | 放 `.vrm` 文件（这个目录在开源版里是空的） |
| `js/room/model-import.mjs` | 拖拽导入：先查骨骼、量身高，不合格当场说清缺什么 |
| `js/room/world.mjs` | 装进来之后：骨骼映射、坐/躺/走的姿势、头发物理 |

**换模型不用改代码。** 把 `.vrm` 拖进页面——它会先查这几件事，不合格不进屋子：

- 有没有 `humanoid`（VRM 0.x / 1.0 都认）
- 身高是不是在房间能容纳的范围（门 1.75、层高 2.05，都是照 1.357 反推的）
- 关键骨骼齐不齐（缺一根，坐下时那条腿就会穿进桌板）

合格就存到 `assets/vrm/` 并登记进 `assets/characters.json`，下次打开还在。

## 二、从哪来一具身体

| 路子 | 成本 | 你能商用吗 |
|---|---|---|
| **VRoid Studio** 自己捏 | 免费，一晚能出第一版 | 你做的，可以（遵守 VRoid 的示例模型条款） |
| **买/委托** 画师 + 建模师 | 几百到几千 | 看合同，一定要写明"可商用、可分发" |
| **用现成的**（ Booth 等） | 便宜或免费 | **逐个看条款**。写着"禁止商用"就只能自己玩 |
| **不想做 3D** | —— | 这个仓库只开了 VRM 后端；Live2D 要自己接 |

VRoid 的导出就是 `.vrm`，拖进来即可。身高不对不要紧：屋子按 1.357 的尺寸做的，
但 `applyPose` 和家具位置都按比例缩放，1.5 米的人也能坐。

## 三、家具

家具是**几何 + 一张贴图**，不是模型文件：

- 尺寸在 `js/room/spec.mjs`（床、桌、椅、门、层高，全是从她的身高反推的）
- 贴图在 `assets/furniture/`，`furniture.json` 里写裁切坐标
- 开源版里这些贴图是**同尺寸的纯色占位**——房间能跑，只是没有样子

换自己的家具：把图放进去、改 `furniture.json` 的 `file` 和 `crop`。
想加一件新家具，见 `assets/furniture/` 里的现有条目和 `js/room/world.mjs` 的搭法。

## 四、一间屋子算不算"框架"

算。屋子本身是框架（墙、门、灯、碰撞、能走进去），
**屋子里摆什么、长什么样**才是内容。所以：

- `js/room/spec.mjs` 里的尺寸是框架（改了要连带动动作和规矩）
- `assets/furniture/*.png` 是内容（换成什么都行）
- `rules/room.json` 里"哪盏灯被拨了要报给她"是框架；具体有几盏灯是内容

想做第二间屋子：复制 `js/room/spec.mjs` 的常量、换 `rules/room.json`、
换 `assets/furniture/`，页面用 `?room=` 选。这是下一版要开的门。
